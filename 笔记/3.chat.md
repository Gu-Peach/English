## 但有两点值得肯定

1. 工程模式是可迁移的 ：checkpointer 做会话隔离、SSE 打字机、reasoning_content 分流渲染、预检索拼 prompt——这套骨架换任何 AI 场景都用得上，这是教程真正的"含金量"；
2. 项目里其实留了一个没被利用的富矿 ：你的`WordBook` 表。目前 AI 聊天和词库是 两座孤岛 ——聊天机器人完全不知道用户背过哪些单词、错在哪里。

## 如果真想“应用于英语学习”，缺的恰好是你已经会接的东西

按投入产出排序：

| 方向         | 做法                                                                        | 用到的已有技能                           |
| ------------ | --------------------------------------------------------------------------- | ---------------------------------------- |
| 个性化出题   | 把用户 `WordBook` 里的高频错词注入 system prompt：“请用这些词出 3 道选择题” | 就是预注入，和 webSearch 同款套路        |
| RAG 词库助教 | 用户问“abandon 怎么用”→ 检索自己的生词本与例句库 → 拼进 prompt              | 你已经理解了预检索机制                   |
| 真·工具调用  | 定义 `addWord` tool，聊天中 AI 主动把生词存进词库                           | `createAgent({ tools })` + reasoner 模型 |
| 对话测评闭环 | 用 reasoner 给用户的英语回复打分，回写 `wordNumber` / `dayNumber`           | Prisma + 现有打卡体系                    |
| 每日提醒升级 | 定时任务（`isTimingTask` 字段已经建好了！）推送基于进度的个性化文案         | 第12招大概率讲这个                       |

注意一个细节：数据库里的 `isTimingTask`、`timingTaskTime` 字段在第7招就埋下了，说明教程后面（定时任务/邮件提醒）才要兑现——同理，WordBook 和 AI 的打通教程可能也不会做，**这正是你把它当练手项目做差异化改造的空间**。
